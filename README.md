# SocketTask

Учебный клиент-серверный проект на C++20. Он состоит из динамической библиотеки и двух программ, взаимодействующих через TCP-сокеты в Linux.

## Возможности

- проверка пользовательского ввода;
- обработка строки функциями динамической библиотеки;
- два синхронизированных потока в клиенте;
- потокобезопасный общий буфер без постоянного опроса;
- передача числового значения через TCP;
- автоматическое переподключение клиента;
- ожидание нового клиента сервером после разрыва соединения;
- отдельные логи клиента и сервера.

## Логика обработки

Программа №1 принимает строку, которая:

- не должна быть пустой;
- должна состоять только из цифр;
- не должна превышать 64 символа.

После проверки динамическая библиотека:

1. сортирует цифры по убыванию;
2. заменяет каждую чётную цифру латинской строкой `KB`;
3. рассчитывает сумму цифр, оставшихся в обработанной строке.

Полученная сумма передаётся программе №2.

Программа №2 считает значение корректным, если:

- его десятичная запись содержит не менее трёх цифр;
- значение делится на 32 без остатка.

Пример:

```text
128 >= 100
128 % 32 == 0
```

Поэтому для значения `128` сервер выводит:

```text
Received data: 128
```

Для остальных значений:

```text
Error: incorrect data
```

### Динамическая библиотека

Библиотека `lib` предоставляет три функции:

```cpp
void lib::processString(std::string& str);
int lib::calculateSum(const std::string& str);
bool lib::checkSum(int sum);
```

Она собирается CMake как `SHARED`-библиотека.

### Программа №1

Клиент содержит два потока:

1. Поток ввода проверяет и обрабатывает пользовательскую строку.
2. Рабочий поток забирает данные из общего буфера, выводит результат, вычисляет сумму и отправляет её серверу.

Для синхронизации используются:

- `std::mutex`;
- `std::condition_variable`;
- FIFO-очереди.

Если сервер недоступен, неотправленные суммы сохраняются в памяти. Клиент периодически повторяет подключение, не останавливая обработку пользовательского ввода.

### Программа №2

Сервер:

1. открывает TCP-порт;
2. ожидает подключения клиента;
3. получает 32-битные значения;
4. проверяет их через `lib::checkSum`;
5. после разрыва соединения снова ожидает клиента.

Сервер обслуживает одного подключённого клиента одновременно.

## Сетевой протокол

Каждое сообщение содержит одно значение `std::uint32_t`, то есть четыре байта.

Перед отправкой клиент вызывает `htonl`, а сервер после получения вызывает `ntohl`. Благодаря этому порядок байтов не зависит от архитектуры компьютера.

Клиент и сервер учитывают, что TCP может отправить или принять только часть данных за один системный вызов.

## Требования

- Linux;
- GCC с поддержкой C++20;
- CMake 3.20 или новее;
- POSIX Threads.

## Сборка

Из корня проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

Собранные программы и динамическая библиотека появятся в:

```text
build/bin/
```

## Запуск

Откройте два терминала.

### Терминал 1 — сервер

```bash
./build/bin/program2
```

### Терминал 2 — клиент

```bash
./build/bin/program1
```

По умолчанию обе программы используют порт `8080`.

Можно указать другой порт:

```bash
./build/bin/program2 9000
./build/bin/program1 9000
```

Порт клиента и сервера должен совпадать. Допустимый диапазон — от `1` до `65535`.

Сервер и клиент разрешено запускать в любом порядке. Если сервер недоступен, клиент будет повторять подключение при наличии неотправленных данных.

## Пример работы

Клиент:

```text
Input a numeric string (up to 64 characters): 123456
Result: KB5KB3KB1
```

В обработанной строке остаются цифры `5`, `3` и `1`, поэтому сервер получает сумму:

```text
5 + 3 + 1 = 9
```

Ответ сервера:

```text
Error: incorrect data
```

Пример строки, сумма которой равна `128`:

```text
9999999999999533
```

## Логирование

При запуске из корня проекта создаётся каталог:

```text
logs/
```

Клиент пишет в:

```text
logs/SocketClient.log
```

Сервер пишет в:

```text
logs/SocketServer.log
```

Логи содержат:

- время события;
- запуск и остановку программы;
- принятые и обработанные данные;
- рассчитанные и отправленные значения;
- подключения и отключения;
- сетевые ошибки.

Пример:

```text
[2026-07-27 12:34:56] Connected to server
[2026-07-27 12:34:56] Sent value: 128
```

Путь `logs/` рассчитывается относительно рабочего каталога процесса.

## Завершение

- клиент можно завершить через EOF (`Ctrl+D` в Linux);
- сервер можно остановить через `Ctrl+C`.

Неотправленные значения хранятся только в оперативной памяти и не сохраняются после завершения клиента.
